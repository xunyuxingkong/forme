# Forme 玩法与视觉体验升级方案

日期：2026-10-10。基于本项目0.2.0代码、功能记录及同类产品官方页面整理。本文是下一阶段设计建议；除明确标注的现状和测量值外，均为待实现、待验证目标。本次只形成方案。

**1．核心判断与优化目标**

当前版本建立了模型切换、移动、场景物件、聊天、记忆和权限等基础，但“功能可用”尚未转化成“愿意反复玩”。主要原因如下。

| 当前问题 | 具体表现 | 优化目标 |
| --- | --- | --- |
| 选择缺少后果 | 很多物件都是走过去、播放动作、显示固定文本 | 操作改变道具、环境或伙伴后续行为，变化看得见 |
| 重复价值低 | 第二次点与第一次点基本相同 | 相同操作因物件组合、位置、伙伴偏好而出现可理解的差异 |
| 宠物形象与行为同质 | 外形不同，互动节奏和动作逻辑相近 | 轮廓、动作风格、兴趣和小习惯共同构成角色辨识度 |
| 场景大而分散 | 20m×20m提供面积，互动点之间缺少联系 | 形成短距离、有关联的活动区域，每个区域有独立玩法 |
| 布置偏外观 | 改颜色、换物件，难以形成自己的生活方式 | 布置决定可发生的活动，同时支持自由审美表达 |
| AI与玩法连接浅 | 主要是文本聊天和动作指令 | AI能理解正在发生的小事件，协助共同创作；离线也能完成核心玩法 |
| 成长缺少情感痕迹 | 次数和解锁比独特经历更突出 | 收藏自己参与的瞬间、物件和习惯，保留个人小世界的历史 |

建议产品定位：**一个可以随手玩、会自主生活、能和你一起布置的桌面小世界。**

下一阶段的主线是：安排物件 → 伙伴回应 → 玩一次小互动 → 产生可见变化 → 留下一件纪念 → 尝试新组合。衡量成功的依据是玩家有没有产生“我还想试试另一种摆法”的想法。

**2．近期同类玩法的借鉴与取舍**

以下选取仍可查到当前官方介绍的代表性作品，代表相关设计方向，不是销量排名，也不证明某个机制适合直接照搬。对Forme的建议是设计推论。

| 作品与官方来源 | 可核实的玩法方向 | Forme可借鉴的部分 |
| --- | --- | --- |
| [Rusty's Retirement](https://store.steampowered.com/app/2666510/Rustys_Retirement/) | 屏幕底部放置农场，作物、自动照料与扩展形成循环 | 忙碌时也能感受到世界缓慢变化，主动参与与后台陪伴分开 |
| [Whimside](https://store.steampowered.com/app/3064030/Whimside/) | 生物收集、组合新生物、探索区域及装饰 | 用组合和发现延长玩法；Forme优先做物件组合与访客发现 |
| [Tiny Glade](https://store.steampowered.com/app/2198150/Tiny_Glade/) | 自由搭建，建筑细节随操作适配，支持随时修改 | 布置操作本身有反馈，路径、家具和装饰形成关系 |
| [Gourdlets](https://store.steampowered.com/app/2013730/Gourdlets/) | 建造环境后居民会生活、阅读、钓鱼等，支持桌面放置模式 | 伙伴主动使用用户布置的环境，让布置有生活结果 |
| [Spirit City: Lofi Sessions](https://store.steampowered.com/app/2113850/Spirit_City_Lofi_Sessions/) | 专注工具、精灵发现、角色与房间定制 | 专注与陪伴场景连接，成长奖励融入房间 |

由这些方向提炼三个重点：低打扰的长期变化、表达自己的布置、规则组合产生的发现。收集应帮助玩家找到新玩法；不要把内容寿命主要交给稀有掉率、等待和签到。

**3．三个可形成辨识度的设计**

**A．会产生生活的布置。** 家具具有可使用的属性，摆放关系会触发事件。例如窗边放坐垫，伙伴会晒太阳；坐垫旁放书，会出现阅读角；雨天窗边再放暖灯，会出现“听雨读书”的小事件。条件不应藏成查攻略的谜题，悬停可以看到“靠近窗边可能有新发现”。

**B．从小世界带回桌面的玩具。** 在花园制作的纸风车、捡回的叶子、解锁的小球，可带到桌面陪伴模式。只在用户打开的小型玩耍区域里互动；收起后恢复普通办公。小屋、户外和桌面共享同一个伙伴与收藏状态。

**C．共同经历成为小世界的一部分。** 完成一次纸船探索，可以获得带自选颜色、当天游戏天气和伙伴印章的船票卡，挂在屋里的相片墙。纪念物继续能互动，例如点击船票重玩当时的路线。卡片依据真实游戏事件生成；AI可以受邀写一句题词，基础卡片由本地模板生成。

创新点在于把“布置、伙伴行为、短玩法、纪念物、桌面陪伴”接成一条有因果的循环。这是Forme的设计方向，不宣称其每个组件在市场上前所未有。

**4．玩法结构与可玩内容**

| 使用时长 | 目标 | 例子 | 结束方式 |
| --- | --- | --- | --- |
| 5–20秒 | 手感与即时回应 | 摸头、抛接球、拨风铃、把叶子递给伙伴 | 随时松手或收起 |
| 1–3分钟 | 做选择、发现差异 | 纸船引航、伙伴藏物、花园弹球 | 一局完成、暂停或直接离开 |
| 5–15分钟 | 创作与个性表达 | 布置阅读角、设计小花园、拼装纸船路线 | 保存布置，之后继续 |
| 数天至数周 | 形成归属与收藏 | 发现伙伴偏好、收集访客印章、形成自己的回忆墙 | 没有连续登录要求 |

玩法第一批做深两种，第三种后置：

| 玩法 | 玩家实际操作 | 可重复变化 | 与世界的连接 | 优先级 |
| --- | --- | --- | --- | --- |
| 纸船引航 | 选船形与颜色，摆放导流叶片，调节风向，把船送到码头 | 路线、障碍、船形和风力组合；操作结果可预览 | 伙伴沿岸跟随或帮助捞船，完成后带回纪念船 | 首批核心 |
| 伙伴藏物 | 选择藏在哪里，观察伙伴寻找；也可由伙伴藏、玩家找 | 家具位置影响遮挡，角色偏好提供可读线索 | 家具参与玩法，熟悉角色习惯能提高判断力 | 首批第二玩法 |
| 花园弹球 | 拖拽蓄力、调整角度，让球经过目标或击响风铃 | 移动挡板、不同弹性和目标布局 | 同一套小球可在桌面与花园使用 | 核心验证后 |

每种玩法至少提供3类会改变策略的变化，而不是只更换颜色。结果应包含路径、声音、动作或物件状态的变化；单独加一句新文案不算新结果。允许无目标自由玩，失败不扣资源，提供放慢速度与辅助操作。

成长采用“发现更多生活方式”：基础家具、路径和关键玩法直接可用；发现事件获得外观、印章或新组合提示。已有成长货币和解锁需要保留兼容，不强制迁移成新经济系统。专注、休息和主动游玩都能获得等价的装饰机会，专注时长不作为核心玩法的入场券。

离线变化用退出和恢复时间做有界结算，例如最多带回3条生活见闻；不在后台模拟所有动作。错过的事件可以再次触发，植物不枯萎、伙伴不受罚，长时间不打开不会损失收藏。

**5．先实现的完整样板：雨天纸船**

建议用这个样板检验产品是否真的变有趣，然后再扩内容。

1. 进入花园后，池塘旁有纸船盒。玩家悬停就能看到“试着放一只纸船”。
2. 选择2种船形之一、3种颜色之一，立即看见成品；关键配置不消耗资源。
3. 拖动一片叶子改变导流方向，调整风向。水面显示短距离预测轨迹。
4. 放船后，小猫沿岸观察，主角芽芽会追着船跑；伙伴外形不影响能否完成。
5. 船抵达不同码头，触发不同动作和纪念图案；卡住可以随时捞回，无惩罚。
6. 玩家把纪念船摆到屋里或桌面玩耍区域，伙伴以后偶尔会主动看它。
7. 可选地问AI“给我们这次旅行取个名字”，仅发送本次选中的游戏事件，不发送全部聊天。

首个样板内容预算：1段池塘路线、2种船形、3个可移动导流物、3个停靠点、4种事件结果、6件可组合生活物件，先完成主角和一个差异明显的动物伙伴的演出。数量是范围控制，不把颜色排列数当成内容数量。

样板验收：首次进入2分钟内能完成一次有反馈的操作；5分钟内能看到至少两种因自己选择而改变的结果；第三次游玩仍存在未试过的有效选择；断网完整可玩。

**6．宠物模型和动画目标**

现有几何模型可继续作为轻量模式和玩法原型。标准模式逐步引入统一美术规范的原创低模资产，先精修主角，再统一其他3种形象。已有4种模型保留，新增物种排在角色质量和玩法之后。

美术方向建议：柔软的手工玩具质感，轮廓简洁，局部有布料、木材或纸张细节。配色保留目前的暖白、浅绿、木色，减少整体灰蒙和材质雷同；伙伴比背景有更明确的明暗与色彩层次。

| 项目 | 优化要求 | 检查方式 |
| --- | --- | --- |
| 轮廓 | 芽芽、猫、狐、企鹅在头身比例、耳尾和步态上明显不同 | 140px左右显示时，遮掉名称仍可辨认 |
| 表情 | 期待、好奇、开心、放松、困倦、疑惑、惊喜、专注 | 通过眼睛、头部、耳尾共同表达，静音仍能理解 |
| 动作 | 起步、行走、奔跑、刹停、转身、坐卧、拾取、放下、抚摸反馈 | 不瞬间转向，不明显滑步，拿起物件有实际接触 |
| 独特表现 | 猫会探爪和扑叶，狐狸嗅闻与摆尾，企鹅摇摆与短滑步，芽芽用叶耳表达 | 共用动作语义，每种角色至少3个独有回应 |
| 触感 | 摸头、侧身、鼻尖有不同回应，触摸方向影响头部转向 | 连续拖动有反馈，点击与拖动不互相误触 |
| 个性化 | 预设配色、围巾/帽子/小包等有限挂点，支持一键恢复 | 3次操作内换装或换预设，不要求编辑文件 |
| 身份与外形 | 名字、已确认记忆和收藏保存在伙伴档案；换形象不丢失 | 外形、动作风格、个性可分别选，也有一键推荐组合 |

动画升级保持动作和模型分离：行为发出“看向、坐下、拿起、抛出”等语义请求，模型适配器映射自己的部件和动作片段。新增交互挂点、手/嘴持物点、视线点和坐姿落点；模型不支持的动作有通用替代，不让某个外形失去玩法入口。

“性格”先使用可编辑的本地偏好，例如好奇、亲近、活跃；状态只表达伙伴，不推断用户心理。有限记录用户在应用内明确完成的游戏行为，可形成“常坐窗边”“喜欢这个球”等可查看、重置的习惯。自动选择行为需要冷却和近期去重，不每帧或每次选择都请求AI。

**7．小屋与室外场景目标**

保留约8.7m×7.3m小屋和20m×20m户外的尺度，先提高内容密度、取景与区域联系。主视角随角色、活动区域和窗口尺寸调整，避免户外一拉远就找不到伙伴。

| 区域 | 视觉改善 | 可玩性改善 |
| --- | --- | --- |
| 小屋窗边 | 光斑、窗帘、局部阴影与前后层次 | 坐垫、书、灯组成阅读角；天气改变生活事件 |
| 小屋玩耍角 | 清晰地毯边界、玩具架、低矮家具 | 投球、藏物、搭积木，玩具摆放影响路线 |
| 小屋生活角 | 零食、床、茶几尺度协调，角色能真正靠近 | 拿取零食、卧下、递物、短动作链 |
| 小屋回忆墙 | 可读的相框、挂钩和纪念物陈列 | 摆放事件卡，查看来源或重玩对应活动 |
| 户外中央草地 | 留出完整活动空间，路径连接相邻区域 | 追球、风筝或弹球；后两项按阶段开放 |
| 池塘和木桥 | 有方向的水纹、岸线高差、石头与水草 | 纸船、投石波纹、捞回物件 |
| 花圃与小径 | 植物分层、季节色彩、可行走的自然路径 | 植物组合吸引可重复出现的小访客 |
| 凉亭与林边 | 灯串、坐处和轮廓明确的背景树丛 | 休息、听风铃、访客停靠与小事件 |

布置升级到“可移动、旋转、吸附、复制、撤销”的家具编辑。首批限制在经过验证的平面/墙面/桌面挂点与区域内，保留通道检查；不立即引入任意地形挖掘。家具阻塞路径时显示原因，自动恢复安全位置；移走正在使用的家具先中止相应活动。

物件需要描述占地、交互位置、动作、状态、收纳归属与组合标签。核心组合首批做8–12条有手工编排的规则，发现后进入图鉴，全部可以重现；不要依赖不可解释的纯随机事件。

视觉优先级为模型比例、材质区分、光照与接触阴影、镜头构图、有限环境动态。动态只放在关注区域，例如一小段水纹、两片叶子、灯光轻变；低配模式提供静态替代。资产风格和授权来源统一，音乐音效需要可长期分发的授权。

**8．交互优化：让操作落在物件上**

主窗口默认以场景为中心，聊天、背包、图鉴与布置使用可收起侧栏。常用入口控制在“伙伴、玩耍、布置、聊天”几个层级，专注从书桌或快捷入口开始。首次使用只指导一次完整互动，其他功能按需要出现。

| 场景 | 操作规则 | 必须提供的反馈 |
| --- | --- | --- |
| 点击地面 | 短点移动；拖动超过阈值视为镜头操作 | 目标标记、短路径提示；不可达时标明遮挡原因 |
| 悬停物件 | 轮廓或轻亮，显示名称和最常用动作 | 区分纯装饰、可操作、暂不可用 |
| 点击物件 | 执行主动作，多动作时弹出至多4项上下文菜单 | 显示“前往、进行中、完成或取消”，不只弹一句文案 |
| 拖动玩具 | 进入抓取、抛掷或摆放状态 | 持物姿态、投掷轨迹/落点预览，松手后有碰撞与声音反馈 |
| 布置模式 | 点击选择，拖动移动，明确按钮旋转，Ctrl+Z撤销，Esc取消 | 吸附轮廓、无效位置、通道检查、未保存提示 |
| 伙伴互动 | 触摸部位有区别，叫回与停止始终可达 | 看向玩家、先回应再执行、可打断当前活动 |
| 小窗口 | 选择正在做的活动后切换局部镜头 | 字体和按钮不随3D缩小；一键找回伙伴、复位镜头 |
| 桌面模式 | 点击显示少量常用动作，主动开启玩耍小垫后才接玩具 | 透明区穿透、窗口不抢焦点、可锁定位置、可一键收起 |

建议鼠标拖动阈值先用6个逻辑像素并在100%/150%/200%缩放验证；保留当前左拖旋转习惯，布置和玩具抓取用明确模式分流。键盘能选择物件、执行、取消，拖拽玩法提供按钮或方向键替代。动画不作为唯一状态提示。

行为优先级：用户停止/隐藏最高，其次用户当前直接操作、用户当轮授权的AI短动作、伙伴自主生活。切换家具、进入布置、窗口失去可交互状态时清理旧目标。自主行为不抢走玩家手里的道具，不自动打开大窗口。

声音遵守总开关、安静和专注模式；只在可见的交互区域播放必要反馈，常驻环境音默认可关闭。主动邀请可选关闭、低频或活跃；默认低频，专注时不弹出邀请、不要求收取奖励。

**9．AI与记忆：服务于正在发生的体验**

AI最有价值的用途是一起想、一起命名、一起布置和回应共同经历。基本行为、事件触发、小游戏判定、奖励和存档由本地规则完成。

| 用户表达 | 建议体验 | 执行方式 |
| --- | --- | --- |
| “陪我安静待会儿” | 伙伴到用户选过的休息处，调整到安静演出 | 既有权限内执行一次短动作，无后续自主网络请求 |
| “把这里变成雨天阅读角” | 提供现有家具构成的方案预览 | 一键应用或撤销；不凭空生成未安装的模型 |
| “给我们今天的纸船旅行取个名字” | 生成短题词，用户挑选保存到纪念卡 | 只分享选中的游戏事件；离线提供本地标题模板 |
| “你为什么又去窗边了” | 根据实际偏好和最近事件解释 | 区分已记录的事实与故事化表达，不编造发生过的行为 |
| “今天想玩点什么” | 根据已开放道具推荐一个可立即启动的玩法 | 推荐对应真实入口；不把每日登录设为前置条件 |

游戏事件、用户长期记忆和本次会话摘要分开：游戏事件可以本地自动记载，但不默认上传；用户私人偏好仍需明确确认后才进入长期记忆。分享某张纪念卡或某次事件只授权该条内容，不能顺带发送整份日记。卡片只渲染应用内世界，不捕获桌面、文件或其他应用。

AI控制升级优先使用“窗边坐垫、当前纸船、左侧码头”等可理解的对象与语义，底层映射稳定ID。请求仅携带相关的少量可交互对象和状态，不把整间屋子的完整数据都塞入上下文。新增控制仍受既有独立权限约束；场景批量布置需预览、原子应用及撤销。

AI建议的动作链限制长度和持续时间，建议最多3个意图、合计30秒；每步检查目标是否存在、权限是否仍开启、当前世界版本是否改变，失败就停止并说明。用户可随时取消，不形成“调用模型→执行→再调用”的自动循环。网络失败、输出不合法或服务停用时，常用交互与本地玩法继续工作。

**10．实现结构、资源与长期维护目标**

当前是WPF原生3D实现。下一阶段先保留现有桌面窗口、SQLite、聊天服务和模型适配边界，用一个精修角色加一个互动区域验证新的资产和演出管线。待画面、动画和资源实测后再决定渲染层是否需要替换；不把全量引擎迁移设成玩法改进的前置条件。

建议模块关系：本地世界状态管理物件与游戏事实；物件规则产生可执行互动；行为选择器选择伙伴的下一步；动作适配器映射不同模型；渲染层负责表现；AI只提交受限意图。窗口共享世界状态，避免桌面和小屋各养一份相互矛盾的伙伴。

家具定义逐步数据化，包括稳定ID、模型、占地、挂点、活动、组合标签和版本。第一批组合仍由人工编排与测试；减少在大型switch中持续堆物件。新增资产有清单、来源与授权；内容包只接受白名单数据与资产，不加载任意脚本。自定义资产缺失时使用默认替代并保留用户布置。

下表是提案阶段的资源上限和发布门槛，尚未实现或实测。以当前测试机及约定显示设置作参考，另补一台集成显卡设备。

| 项目 | 建议目标 | 验证方式 |
| --- | --- | --- |
| 桌面伙伴待机 | 平均私有内存≤100MiB，归一化整机CPU≤1% | 预热后采样30分钟，注明12逻辑处理器参考环境和显示缩放 |
| 小世界待机 | 平均私有内存≤250MiB、同口径CPU≤2% | 标准资产和可见世界采样30分钟 |
| 主动游玩 | 默认30FPS；帧耗时P95≤40ms；无需默认60FPS | 池塘玩法、镜头移动、聊天流式同时进行 |
| 本地操作反馈 | 点击、拖动、取消的可见反馈P95≤100ms | 记录输入到反馈，不把完整动画时间算为响应延迟 |
| 冷启动 | SSD参考机首次可操作目标≤3秒 | 分别记录首次安装启动与后续启动，后者作为优化基线 |
| 收起/隐藏 | 停止3D动画与粒子计时，无后台AI请求 | 计时器、GPU活动和请求计数检查；必要功能计时独立运行 |
| 长期运行 | 稳定缓存后8小时内存无持续增长，100次窗口切换无对象泄漏 | 对比预热后与结束状态，记录句柄、模型和计时器存活 |
| 模型资产 | 单角色高档目标8k–15k三角形，低档2k–5k；解码纹理≤16MiB | 资产导入检查，实际渲染仍以帧耗时和内存验收 |
| 常驻开销 | 仅渲染当前伙伴与当前区域；桌面模式不持有完整户外世界 | 状态切换后检查资源释放；访客数量有界 |

现有短采样基线为小猫待机约55.67MiB/0.39%CPU、户外约133.99MiB/0.82%CPU，采样仅20秒，GPU未测；详见 `0.2功能与验证记录.md`。新预算允许有限增加美术与玩法成本，但不能把这组短采样当成长期性能保证。GPU另记录进程3D活动、显存、整机功耗变化和集成显卡结果，建立参考后再确定硬件分档阈值。

行为选择采用事件触发与低频评估，活跃时才增加频率；离线事件采用有界时间结算。物件动态使用简化规则与受控运动，不为全部家具常驻运行完整物理模拟。静态几何、材质和阴影资源尽量复用；高档水面、柔和阴影等效果必须有降级方案。

所有不含AI的玩法请求数为0；用户主动一次AI操作默认最多一次请求，无自动重试。沿用可配置的上下文与输出上限，预算不足先缩减无关场景信息。费用提示区分本地估算和服务商实际账单，不承诺模型价格、月费用或服务响应时间。

本地游戏与聊天记录支持按类别导出、删除和迁移，角色档案与布局版本化；升级前备份，动作奖励采用幂等事件ID，避免重试/恢复重复领取。事件与物件状态事务保存，退出或中断后回到稳定状态，不恢复一半的AI控制链。

**11．开发顺序、依赖与完成条件**

| 阶段 | 主要交付 | 依赖与复杂度 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| A：先验证有趣 | 雨天纸船样板、伙伴跟随参与、物件拖拽与撤销、纪念船、主角及1种动物演出 | 中高；先建立物件状态与语义动作边界 | 5分钟能完成并主动试第二种方案；断网可玩；输入不冲突 |
| B：让世界活起来 | 基础家具编辑、8–12条组合事件、伙伴偏好、自主生活、伙伴藏物、桌面玩具 | 高；依赖可取消动作链、家具挂点、可达性检查 | 玩家能解释布置如何影响行为；后台陪伴不干扰工作；保存恢复正确 |
| C：统一模型与场景品质 | 4种形象精修、每种至少3个独有回应、室内外分区、材质灯光、少量访客和收藏 | 高，资产工作量突出；与A/B的局部精修同步推进 | 小尺寸可辨认，角色与物件接触自然，达到性能预算和可读性验收 |
| D：AI共同创作 | 语义对象控制、布置方案预览、事件题词、基于实际事件的聊天 | 中高；依赖稳定对象ID、事实记录、事务与撤销 | 权限关闭时无动作，旧状态方案不误执行，真实服务经过人工联调 |
| E：按反馈扩展 | 第三种玩法、主题内容包、更多组合/访客、可导出的布局 | 中；依赖内容规范及性能回归 | 前面两种玩法已有重复游玩证据，内容可独立添加和回滚 |

优先级顺序：互动手感与一个完整循环 → 伙伴行为差异 → 布置与事件联系 → 视觉整体一致性 → AI增强 → 扩大内容数量。A阶段就要有局部美术精修，不能等全部功能做完才发现模型无法支撑互动。

暂不列入这一轮：多人实时世界、大地图开放探索、自由繁殖生成任意模型、复杂经济链、无上限自动AI代理、重型UGC脚本系统。它们会显著增加同步、审核、资源或维护成本，且不能直接解决当前互动缺少结果的问题。

阶段数量不等于版本数量，本文不承诺工期。先完成A的可玩样板和资产管线试验，再依据实际工作量给B–E排期；玩家反馈可能让后续项目合并或取消。

**12．体验验收与验证安排**

实施进度（0.3.0）：先交付A阶段“雨天纸船”的完整本地操作循环、路线预览、叶片拖拽与撤销、伙伴放船/欢呼、收藏重玩和小屋陈列。详情见[0.3玩法升级与验证记录](0.3玩法升级与验证记录.md)。这不代表A阶段资产管线试验、用户试玩验证或B–E阶段已经完成；后续范围仍依据本方案的阶段门槛推进。

实施进度（0.4.0）：交付本批B阶段家具编辑、8条组合事件、双向藏物和交互反馈，并局部精修芽芽/小猫。详见[0.4功能与玩法升级记录](0.4功能与玩法升级记录.md)。后台自主生活、桌面玩具小垫、全部模型/场景重制、AI共同创作和第三玩法尚未完成。用户要求性能专项测试后置，功能与生命周期检查继续保留。

实施进度（0.5.0）：完成D阶段共同创作的调用基础：独立授权、家具位置/旋转预览与手动保存、阅读角模板、组合事件/藏物/抛球/纸船调用及旅行命名，补齐有界顺序执行与停止。详见[0.5AI共同创作与验证记录](0.5AI共同创作与验证记录.md)。事件叙事卡、更多语义布置模板和可导入内容包仍待后续实现；后台自主生活、桌面玩具垫、完整美术重制和第三玩法状态不变。

以下是建议验收目标，不是已有用户研究结论。先邀请5–8名目标用户做观察性试玩，覆盖喜欢布置、主要用来专注、主要想与宠物互动三类使用方式；单人项目也可先由项目用户分3天完成同样任务。小样本用于发现问题，不推断市场留存率。

| 维度 | 要观察的行为与目标 |
| --- | --- |
| 可发现性 | 至少80%受测者不用口头指导，在2分钟内完成第一次物件互动 |
| 重复价值 | 至少80%在5分钟样板中尝试第二种摆法或路线；能说出结果为何不同 |
| 主动兴趣 | 给出“可继续也可结束”的选择，记录是否自发尝试新组合及原因，不用奖励诱导 |
| 个性辨识 | 不显示名字时能分辨模型；观察两段行为后能描述至少一个角色差异 |
| 创作表达 | 3次主要操作内完成换装或应用布置模板，撤销后无数据丢失 |
| 桌面打扰 | 30分钟办公测试无抢焦点、透明区域挡点击、强制弹窗与任务栏越界 |
| 无障碍 | 核心互动可用键盘/按钮替代；减少动效、静音仍能完成两种玩法 |
| 隐私理解 | 用户能在发送前找到实际共享内容，知道游戏日志与AI记忆的区别 |
| 可靠性 | 关闭、崩溃恢复、导入旧备份、模型缺失和断网后仍能继续本地体验 |

观察重点包含“哪里犹豫、哪里误点、为什么再玩、为什么退出”，以录入的试玩笔记为主。不默认上传用户行为日志；调试统计限本机、可关闭，不收集聊天原文、屏幕或其他应用活动。

若样板的二次尝试率和反馈不达标，优先重做操作、差异与奖励连接，再做新模型或扩大场景。完成标准是用户理解并愿意重复这个循环，而不是页面数、模型数或功能数增加。

**13．对应项目思想准则的检查表**

| 准则 | 本方案的明确落实 |
| --- | --- |
| 接口成本 | 核心玩法与自主生活本地执行；AI只由用户主动发起且请求有上限 |
| 响应延迟 | 即时本地反馈；网络等待不阻塞玩具、移动或取消 |
| 隐私边界 | 游戏事件与私人记忆分开；共享最小相关内容；布局/卡片导出可预览 |
| 长期可用性 | 断网可玩；模型和内容有版本与替代；数据可迁移；AI服务可替换 |
| 定制路径简单 | 预设、直接拖拽、上下文操作与撤销；高级参数不挤进常用入口 |
| 资源占用低 | 分档美术、低频行为、有界缓存、隐藏停止渲染、长时间实测 |
| 隐私边界清楚 | 明确区分本地玩法、已共享记忆、当次事件；提供实际发送预览 |
| 长期维护省心 | 稳定语义动作、数据化物件、人工可测组合规则、先验证再扩内容 |
