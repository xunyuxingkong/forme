# 0.5 AI 共同创作

本批把已实现的本地玩法接入现有外部聊天接口。沿用兼容 chat/completions 的流式文本协议，服务返回 `forme-actions` JSON 意图，本地白名单检查后执行；不要求服务商支持原生 function calling。不增加依赖或后台推理服务。

## 用户入口与可用范围

在“设置 → 伙伴角色、记忆与动作权限”分别开启所需权限，点击保存。旧版本权限保持原含义，新增“玩法调用”和“家具预览”默认关闭。

- 宠物：原有动作、待机、坐标移动，加四种已安装模型切换、停止、叫回。
- 玩法：当前满足条件的8种组合事件、伙伴藏用户找／用户藏伙伴找、指定落点抛球。
- 纸船：打开、放船、暂停、继续、捞回；船形、颜色、风向、三片叶的位置与导流角；为已完成旅行命名。配置可在纸船侧栏撤销，命名不自动收藏。
- 家具：阅读角模板；按现有家具编号调整位置与90度旋转；撤销草稿。所有提案先验证边界、重叠和通道，失败不改变草稿。只预览，点击“保存家具布置”才落盘；离开取消。模板以基础6件家具替换草稿，可撤销。

示例：“帮我布置阅读角，先给我预览”“开启雨天和暖灯”“体验当前能发生的阅读事件”“让伙伴藏东西，我来找”“把船变成粉色，风吹向柳树，再放船”“走到空地坐标1、1，再拍拍”“切换为小猫”。一次最多3步，复杂要求可分次提出；AI理解和指令生成效果取决于所配模型，不保证每次都能生成有效指令。

## 执行与故障边界

只有完整、未取消、未达到输出上限的回复才执行。参数、权限在解析和执行时各检查一次。移动、短动作和物件互动等待完成后才执行下一步；整组最多30秒，局部失败、手动停止／互动、隐藏或最小化中止剩余步骤。纸船与藏物独立运行，不等待整局结束、不自动回调AI。结果写在回复下方，进入后续聊天上下文前去除指令与本地报告，避免历史动作重放。

聊天的“停止”取消联网／当前动作组，小屋顶部“伙伴控制 → 停止当前活动”和桌宠“停止动作”中止当前活动。调用失败不会自动重试或联网续接。家具保存、收藏、数据删除、凭据与系统操作不开放给AI。家具编号失效、事件条件不满足、旅行未完成等由本地拒绝。

## 四项约束与四项体验指标

- 成本：仅用户发送聊天产生原有单次请求，最多3个本地动作，无后台调用、自动追问、重试或事件循环。沿用输出与上下文预算，收费由用户服务商承担。动作等待不占用额外API请求。
- 延迟：WPF异步等待不阻塞窗口和渲染，100ms间隔仅在动作组活动时检查完成条件；整组30秒上限。界面先显示发起结果，完成后保存报告。真实服务首字延迟和成功率待用户密钥验证。
- 隐私：权限开启前界面明确发送范围。玩法权限发送可用事件ID、藏物公开线索、纸船当前配置和当前旅行名字；家具权限发送最多24件家具的编号、种类、位置与旋转，不发送图鉴发现、历史收藏或藏物答案。仍可预览实际发送内容。状态过大时省略场景数据并标记裁剪，无法容纳必要指令时拒绝发送并提示调整预算。角色、记忆沿用已有显式共享规则。
- 可用性：游戏仍由本地规则处理，断网保留全部手动功能；不依赖单一AI服务或原生工具调用。旧设置缺少新增开关时为false，不需要数据库结构迁移。
- 定制：两个独立开关、现有角色设置和现有草稿编辑器，无需源码或额外配置文件。权限可撤销、布局可撤销或取消。
- 资源：无常驻新增渲染器、网络轮询或背景模型；沿用原有游戏定时器。只说明实现边界，不把其写成实测性能结论；性能专项按用户要求后置。
- 维护：协议与白名单在Core，WPF执行桥在AiCreation；模型仍通过语义动作适配。没有把模型几何交给AI。
