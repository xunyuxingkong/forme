# Forme 初版产品设计

版本：v0.3 设计稿（开发准则复核与 3D 展示要求）  
日期：2026-10-09  
目标平台：Windows 桌面  
状态：供评审和后续开发使用，本文不代表功能已经实现。

## 1. 产品定位

Forme 是一个住在 Windows 桌面上的陪伴小屋。它将桌面伙伴、小世界、情绪陪伴和专注活动融合在同一个工具中，让用户在工作和生活之间随时获得轻互动、放松和陪伴。

首版的核心价值：有一个愿意打开的小空间，有一个愿意互动的小伙伴，并且专注、休息、记录心情这些日常活动确实可用。

本设计受项目根目录 `AGENTS.md` 约束：同时评估接口成本、响应延迟、隐私边界和长期可用性，并以定制路径简单、资源占用低、隐私边界清楚、长期维护省心作为验收依据。以下数值为首版设计预算和待验证目标，不是已有测试结论。

### 1.1 设计原则

- 陪伴自然：角色有反应、有状态，但不要求用户持续照顾。
- 操作直接：常用活动两次点击内可以开始，动画不阻塞操作。
- 安静可控：主动招呼、声音、通知、置顶和自启动均由用户控制。
- 本地优先：房间、专注、心情记录和解压互动在未配置 AI 或断网时正常工作。
- 无负担成长：不设饥饿、生病、死亡、断签惩罚、连续打卡压力和排行榜。
- 功能与场景一致：物件可以作为入口，同时保留文字按钮，避免只能猜测可点击区域。
- 情绪表达由用户掌握：不通过摄像头、麦克风、屏幕监控或后台行为推断情绪。

### 1.2 首版用户与使用场景

主要面向长期使用电脑、希望桌面更有温度，也需要轻量专注和休息支持的个人用户。

典型场景：

1. 开机后伙伴在桌面出现，用户点击它获得简短反馈。
2. 开始工作前，从小屋书桌启动一段专注，伙伴同步进入安静陪伴状态。
3. 心情烦躁时，打开聊天或玩一分钟左右的解压互动。
4. 下班前记录今天的心情，看一眼专注记录和房间变化。
5. 忙碌时收起角色，只保留托盘，需要时再唤回。

## 2. 初版范围与完成边界

“初版可用”指形成完整的安装、首次使用、日常使用、退出恢复和数据管理流程，不以静态原型或只能在线演示的页面作为交付。

### 2.1 必须交付

| 模块 | 初版交付内容 | 范围约束 |
| --- | --- | --- |
| 桌面伙伴 | 真正 3D 角色、透明窗口、拖动、点击反馈、状态动作、快捷菜单、显示与收起 | 一个默认角色，支持改名，不提供角色编辑器 |
| 小屋 | 一个 3D 房间、固定功能物件、可调整视角、昼夜主题、有限装饰位 | 不做自由建造、地图漫游、物理碰撞和多房间 |
| AI 聊天 | 文本对话、流式回复、中止、重试、会话管理、连接设置 | 一个经过实测的服务适配，允许保存一个当前连接 |
| 情绪陪伴 | 可选心情记录、短备注、历史查看、聊天陪伴、引导放松 | 不做情绪诊断、自动情绪识别和治疗承诺 |

| Windows 基础体验 | 托盘、安装卸载、单实例、多屏与缩放适配、恢复与错误提示 | 第一阶段验收 Windows 11 x64；其他系统单独验证 |

### 2.2 明确后置

复杂工作自动化、文件批量处理、屏幕读取、语音对话、联网搜索、提醒事项系统、日历接入、多宠物、角色市场、社交、云同步、多房间和跨平台版本。

这些是可能的后续扩展，不视为已批准的开发内容。

## 3. 产品形态与导航

### 3.1 桌面形态

透明背景的小角色，默认视觉尺寸约 140–180 逻辑像素，可调节大小。默认不置顶、不播放声音，通过任务栏和托盘也可以找到小屋。

- 单击角色：播放短反馈，展示包含“打开小屋、聊一会儿、开始专注、放松一下”的快捷气泡。
- 拖动角色：超过拖动阈值后移动窗口，松开时不得误触单击。
- 右键角色：打开文字菜单，提供打开小屋、安静模式、大小、置顶、收起到托盘和退出。
- 拖到屏幕边缘：允许吸附；收起到边缘需有明确操作，不因偶然靠近边缘自动消失。
- 收起后：托盘可以恢复；若位置失效，自动回到当前主屏可见区域。

透明窗口的非角色区域不拦截鼠标。菜单打开期间可正常操作菜单；角色默认不抢键盘焦点。首版不需要角色自由横穿桌面或攀爬其他窗口。

### 3.2 小屋形态

独立窗口，建议初始尺寸 1000 × 720 逻辑像素，允许缩放；小屏下内容重排，设置页可滚动。具体最小尺寸在实现时通过实机确定。

布局：

```text
┌────────────────────────────────────────────────────────────┐
│ Forme · 伙伴名字             当前状态         安静   设置     │
├──────────────────────────────────┬─────────────────────────┤
│                                  │ 活动面板                │
│          3D 小屋场景              │ 聊天 / 专注 / 心情       │
│                                  │                         │
│  窗户       书桌       植物        │ 当前内容与操作           │
│       伙伴          休息角         │                         │
├──────────────────────────────────┴─────────────────────────┤
│ 聊一会儿      专注      放松      心情      布置               │
└────────────────────────────────────────────────────────────┘
```

窄窗口下场景和活动面板上下排列或以页签切换。小屋关闭时默认回到桌面伙伴形态；首次关闭时简短解释。退出程序必须在菜单里有明确入口。

小屋打开时桌面角色暂时隐藏，关闭小屋时按用户此前的显示状态恢复；不会同时出现两个可交互的伙伴。

### 3.3 房间物件与功能映射

| 物件 | 点击行为 | 状态反馈 |
| --- | --- | --- |
| 伙伴 | 打开聊天 | 挥手、聆听、思考、回应 |
| 书桌 | 打开专注面板 | 专注时台灯和坐姿变化 |
| 休息角 | 打开放松活动 | 休息时伙伴坐下或伸懒腰 |
| 心情本 | 打开心情记录 | 当天有记录时出现书签 |
| 植物 | 查看成长与浇水 | 按规则切换成长阶段 |
| 装饰架 | 打开布置面板 | 展示已选择的装饰 |
| 窗户 | 查看并切换昼夜外观设置 | 随本地时间或手动主题变化 |

物件悬停时有名称提示和轻微高亮，键盘可以访问等价按钮。昼夜变化仅使用本地时间，不获取地理位置或真实天气。

## 4. 视觉、声音与角色设计

### 4.1 视觉方向

按用户明确要求，采用柔和的风格化 3D 宠物和 3D 小屋：奶油色背景、低饱和绿色和暖棕色、圆润角色、真实网格与灯光。房间支持在有限范围内转动视角、滚轮调整距离和复位；物件使用真实 3D 命中测试，同时保留文字导航。色彩服务于状态区分，正文必须保持可读对比度。

首版以原生桌面 3D 能力绘制低复杂度模型，共用几何体和材质，不默认引入独立游戏引擎、物理模拟或远程模型下载。空闲不运行连续渲染循环，隐藏时释放视图；如果实测无法满足既定资源预算，需说明差距并评审，不直接放宽目标。

默认角色暂定为容易表达情绪的小生物，名称和最终外观在美术阶段确定。首版只制作一个角色，保持桌面、小屋、图标和对话头像的一致性。

避免将所有按钮都隐藏在场景内。活动面板优先清晰、易读，常见操作有明确文字。

### 4.2 最小动作资产

| 动作 | 触发 | 播放规则 |
| --- | --- | --- |
| 待机 | 无活动 | 低频呼吸、眨眼 |
| 问候 | 主动点击或首次打开 | 短动作，不连续刷屏 |
| 被拖动 | 拖动开始到松开 | 随拖动状态结束 |
| 被揉揉 | 用户进行对应交互 | 短反馈，可中断 |
| 聆听 / 思考 | 对话请求中 | 有文字状态，不只靠动画 |
| 回应 | 回复完成 | 短动作，不逐字触发 |
| 专注 | 专注计时中 | 安静循环，降低动作频率 |
| 休息 | 休息计时或放松中 | 伸懒腰等低频动作 |
| 睡眠 / 安静 | 用户选择安静外观 | 静态或极低频动作 |
| 开心 | 活动完成或获得装饰 | 可被减少动效设置替换 |

### 4.3 性格与边界

默认性格温和、略有幽默，不说教，不要求用户回应，不因用户离开表达责备。默认回复简短，用户需要时再展开。

不声称拥有真实身体感受，不以“你不来我就很难过”等方式制造负担。角色不会自行承诺提醒、操作系统或完成尚不具备的工作。

声音默认关闭；启用后区分互动音效与计时提示音，分别调节。提供减少动效选项，关闭漂浮、缩放等明显运动。

## 5. 首次使用流程

1. 首次启动展示简短介绍：“一个陪你专注、休息和聊天的小伙伴”。
2. 用户可以修改伙伴名字和自己的称呼，也可以直接使用默认值。
3. 选择展示偏好：桌面伙伴、默认安静、是否置顶；自启动默认关闭。
4. AI 配置可跳过，清楚说明未配置时仍可使用的功能。
5. 进入小屋，以可跳过的三步引导介绍伙伴、书桌和放松入口。

AI 未配置时不伪装成已具备自由对话能力。聊天面板展示连接设置入口和简单的固定互动按钮，并标注这些是本地互动。

首次引导只要求必要选择，其余使用默认值。名字、外观、声音和专注时长均可通过界面修改和恢复默认，不要求编辑配置文件；恢复外观或偏好默认值不删除历史记录、不重置 AI 凭据。

## 6. 聊天与情绪陪伴

### 6.1 聊天基础

- 支持中文文本输入、多行编辑、发送、流式展示、停止生成、复制回复和重试失败消息。
- Enter 发送，Shift+Enter 换行；中文输入法正在选词时不得触发发送。
- 一次只生成一个回复；生成期间草稿可编辑，下一条消息暂不发送。
- 支持新建会话、查看历史、删除单个会话和清空历史。
- 输入、上下文和回复采用第 6.5 节的固定预算；上下文截断时提示“较早对话未发送”，不会无限发送全部历史或默默截断当前输入。
- 停止生成后保留已生成部分并标记“已停止”；失败重试保留原用户消息，不重复插入。
- AI 生成的富文本按安全子集渲染，禁用脚本、内嵌网页及远程图片自动加载；链接由用户点击后通过系统浏览器打开，避免显示回复本身触发第三方请求。

### 6.2 AI 连接

首版采用用户自行提供 API Key 的方式。对唯一经过验证的服务提供本地预置的地址和推荐模型，普通流程为“选择服务 → 填入密钥 → 测试连接”；服务地址和自定义模型收进高级设置。配置错误在原位置解释并可修正，不要求用户理解接口协议。服务预设随应用版本维护，不后台拉取配置或自动切换服务、模型。

开发阶段选定并验证一个具体服务及接口协议，发布说明列出实际验证范围，不以“全部兼容”作为承诺。不在应用中内置公开共享密钥，也不默认提供免费推理额度。

首次联网前说明：发送消息时，选中的服务会接收当前消息、必要对话上下文及用户已允许的偏好信息，服务使用可能产生费用。默认使用 HTTPS；如支持本机模型，可仅为本机地址允许 HTTP。

连接测试只在点击时执行，发送固定的非个人测试内容，并在按钮旁说明可能产生少量费用；不发送历史记录，不在启动、打开设置或失败后自动重复测试。保存配置本身不触发推理请求。

聊天面板持续显示当前服务、模型及“消息将发送至该服务”的简短说明。更换服务地址或模型不会自动重发内容；更换服务地址后默认新建会话，旧会话保留本地可读。若用户要继续旧会话，需先明确确认将其中的上下文发送给新地址。凭据仅发送给已配置的目标，不随跨源重定向转发。

### 6.3 心情记录

- 用户主动选择“愉快、平静、一般、低落、烦躁”等描述，也可以选择“不想分类”。
- 允许补充短备注，一天可以记录多次，支持编辑和删除。
- 历史按日期列表展示，不打心理健康分数、不生成未经支持的心理诊断。
- 保存记录后可选择“聊聊这个”或“做个小放松”，不自动发送给 AI。
- 只有用户选择“聊聊这个”并发送时，当前记录才加入对话；其他记录默认不进入上下文。
- 不设置每天必填，也不因为没记录而主动追问。

### 6.4 记忆与陪伴风格

首版只保存明确设置的称呼、伙伴名字和回复偏好，不自动提取长期敏感记忆。聊天历史用于用户查看；发送给模型的上下文只来自当前会话的有限窗口及上述偏好。

用户可以随时查看、修改和删除偏好。删除会话意味着删除本地保存的会话，不声称能够删除第三方服务已经收到的数据。

遇到明显的严重危机表达时，回应应认真、简短，鼓励用户联系现实中的可信赖的人或适当的紧急支持；停止俏皮奖励反馈，不将自己描述为专业治疗替代品。

### 6.5 调用成本与延迟预算

以下为实现时必须落实的首版边界。模型选择后验证其可支持性，不能因为接口不支持而静默取消限制。

| 项目 | 首版规则 |
| --- | --- |
| 触发边界 | 只有主动发送、主动重试和主动测试连接可触发请求；角色动作、成长、心情保存、主动招呼不调用 AI |
| 请求数量 | 一次发送最多一个推理请求；不额外调用模型做情绪分类、标题生成、摘要或动作选择 |
| 并发与重试 | 聊天和连接测试共用一个在途请求限制；无自动重试、自动续写、自动备用模型或服务切换 |
| 单次输入 | 最多 2,000 个 Unicode 字符，超出时保留草稿并提示缩短 |
| 输入上下文 | 包含角色说明、偏好、当前消息和历史的合计输入目标上限为 4,096 tokens；按完整消息移除最早历史，优先保留当前输入 |
| 输出 | 单次最多 512 tokens，默认简短回复；超限结束时说明原因，不自动续写 |
| 预算实现 | 优先使用对应模型的本地分词工具；无可靠分词工具时采用有文档依据的保守估算和字符上限，不为计算 token 额外调用服务。若必要内容本身超限，发送前拦截 |
| 发送反馈 | 点击后 100ms 内显示本地发送状态；5 秒仍无内容时显示“仍在等待服务响应”，保持取消可用 |
| 超时 | 首个内容片段等待上限 30 秒，流式内容停滞上限 20 秒，单次总时长上限 90 秒；到限取消并保留已有内容 |
| 取消 | 立即停止本地展示并取消传输，不保证服务端已经停止计算或免除已发生费用；迟到回调不得继续写入已删除或重置的会话 |

上下文不会通过额外摘要请求扩大隐私范围或引入隐藏费用。已停止和失败的部分回复默认不进入下一次上下文，用户已发送的消息仍受正常上下文窗口管理。

单次 token 限额只能约束每次请求，不能保证整月账单上限。使用费用由用户承担；设置说明引导用户在服务商侧配置可用的额度限制。首版不增加本地计费仪表盘，也不把估算金额当成服务商账单。

开发验收以固定脚本（例如每次会话 10 次往返、每天 3 次、每月 30 天）估算月用量，包含逐次累积上下文、输出、连接测试和手动重试。选择服务时记录官方单价来源及核验日期，提供典型与上限场景；价格变化后重新核验。模拟服务用于验证超时和请求数量，真实服务用于测量首内容延迟与完整回复延迟，避免重复付费测试。

## 7. 专注与休息

### 7.1 操作流程

点击书桌或“专注” → 可选填写本次想做的事 → 选择时长 → 开始 → 暂停/恢复/提前结束 → 完成反馈 → 用户选择开始休息或返回小屋。

预设专注时长为 15、25、45 分钟，支持 1–180 分钟自定义；休息提供 5、10、15 分钟和自定义。默认不自动开始下一轮，休息与专注均需用户主动确认开始。

### 7.2 计时与记录规则

- 专注任务只有一个，桌面气泡、小屋和托盘显示同一状态。
- 暂停时间不计入专注时长；提前结束记录实际有效时长，并标记“提前结束”。
- 达到目标记录为“完成”；不因提前结束扣除成长或给出责备文案。
- 运行中的时长使用单调计时来源，避免用户修改系统时间引起跳变。
- 系统睡眠或锁屏时自动暂停；恢复后保持暂停，并提示用户选择继续或结束。
- 退出程序时保存暂停状态；重启后提供恢复入口，离线期间不自动累计。
- 异常关闭后根据最近保存的进度恢复为暂停状态，标明恢复原因。
- 历史保存开始时间、目标时长、有效时长、结果和可选任务名称。
- 完成事件只记录一次，防止重启、重复通知或多窗口触发重复累计。

### 7.3 专注期间行为

伙伴切换为安静姿态，停止主动聊天气泡。用户主动聊天或打开其他面板不结束计时；打开解压活动时给出“暂停专注并放松”按钮，明确执行后才切换活动。

计时完成时应用内展示完成状态；系统通知和声音分别遵循设置。系统通知被禁用时，应用内状态仍然完整，不反复弹窗催促。

## 8. 放松与解压

### 8.1 揉揉伙伴

通过专门的“揉揉”入口进入互动，避免与窗口拖动冲突。按住或轻划时出现弹性变化与表情，松开恢复。支持鼠标和键盘等价操作，减少动效模式使用轻微颜色或表情反馈。

### 8.2 戳泡泡

在活动面板内展示一小片泡泡，点击产生视觉反馈，可选音效。提供“换一批”和“结束”按钮，无倒计时压力、成绩排行或失败状态。小游戏不会自动全屏或遮挡其他应用。

### 8.3 呼吸节奏

提供约一分钟的吸气、呼气节奏动画和文字提示，不要求屏息。可以暂停或随时结束；不以完成时长评价效果。用户不舒服时可直接退出，减少动效模式保留文字节奏提示。

三类活动均离线可用，不需要 AI 请求。完成后轻量询问“再待一会儿 / 回到小屋”，不强制填写心情。

## 9. 小世界与轻成长

### 9.1 房间布置

首版采用固定布局和有限装饰位，提供墙面主题、桌面摆件、地毯三个位置，每个位置少量选项。选择即可预览，保存后生效，取消恢复原配置。

基础房间从首次使用开始就完整可用，核心功能不受解锁限制。

### 9.2 植物成长

- 用户每天可主动浇水一次，每次推进一个成长点；重复点击仅产生反馈。
- 植物以 0、2、5 个成长点展示三个阶段，成熟后保持，不枯萎。
- 按本地日期判断每日浇水；记录已领取日期，时钟回拨不重复领取同一日期。
- 专注结果、心情好坏和聊天次数都不影响植物健康。

### 9.3 装饰解锁

首版只需三项明确里程碑，例如第一次完成专注、第一次完成放松活动、植物成熟，各解锁一个装饰。首次专注里程碑要求有效时长至少 5 分钟；短时长功能仍可正常使用。

解锁在本地完成，每项只发放一次。用户关闭成长提示后，装饰仍正常到账，可在布置面板查看。导入记录不会反复播放历史庆祝。

## 10. 全局状态与主动行为

### 10.1 状态分层

避免用一个“心情状态”控制所有功能，分开管理：

- 展示状态：桌面、小屋、边缘收起、仅托盘。
- 活动状态：空闲、专注、专注暂停、休息、放松。
- 对话状态：未配置、就绪、请求中、已停止、错误。
- 安静偏好：普通、安静、减少动效。

活动状态独立于页面切换。对话动画不得覆盖专注计时；短暂点击反馈结束后恢复当前活动动作。

### 10.2 主动招呼规则

默认关闭定时主动招呼。启用后只使用本地预置的轻量文案，不自动调用 AI；每日至多两次、间隔至少两小时，可设置允许时段。安静模式、专注中、锁屏时不触发，恢复时不补发积压招呼。

首版不根据正在使用的软件内容主动插话。所有气泡自动消失，不抢焦点，用户可以立即关闭。

## 11. 设置、隐私与数据

### 11.1 设置分组

| 分组 | 设置内容 |
| --- | --- |
| 伙伴 | 名字、用户称呼、大小、主动招呼 |
| 显示 | 桌面显示、置顶、昼夜主题、减少动效 |
| 声音与通知 | 音效、计时声音、系统通知、安静模式 |
| 专注 | 默认专注与休息时长 |
| AI | 服务地址、模型、API Key、连接测试、回复偏好 |
| 数据与隐私 | 保存位置、导出、导入、删除会话、清空记录、重置 |
| 应用 | 开机启动、版本、日志位置、退出 |

常用项优先展示，高级连接参数折叠。每项设置提供合理默认值，设置生效时机明确；不把调用预算、渲染帧率等工程参数全部暴露给普通用户。

### 11.2 本地数据结构

| 数据 | 主要字段 |
| --- | --- |
| 用户设置 | schemaVersion、称呼、偏好、窗口位置、显示器与缩放信息 |
| 伙伴与房间 | 名字、主题、装饰选择、植物成长、解锁列表 |
| 会话与消息 | 会话 ID、消息 ID、角色、内容、时间、完成/停止/失败状态 |
| 心情记录 | 记录 ID、心情标签、备注、创建和修改时间 |
| 专注记录 | 任务 ID、名称、开始时间、目标和有效时长、结果 |
| 活动恢复点 | 当前活动、已用时长、保存时间、恢复状态 |
| 成长事件 | 唯一事件 ID、事件类型、关联活动、领取日期 |

数据放在当前 Windows 用户的应用数据目录。普通记录不默认宣称加密，隐私说明需准确反映实现。API Key 通过 Windows 支持的凭据保护方式保存，不写入普通配置、聊天记录、日志、导出文件或仓库。

### 11.3 导入、导出与删除

- 导出版本化 JSON，用户选择包含聊天、心情、专注和房间哪些数据；不包含凭据和诊断日志。
- 导出前提醒文件可能包含私人内容，由用户选择保存位置。
- 首版导入不做记录合并；仅替换导出文件中明确包含的数据类别，未包含的类别保持不变。先校验格式和版本，展示各类别将被替换的记录数量，明确确认后执行；AI 连接和凭据不随内容导入覆盖。
- 替换前生成一个本地恢复备份并告知位置；备份保留至下一次成功替换或用户主动删除。
- 导入失败必须保留原数据，不能留下半导入状态。
- 普通删除同步处理关联索引，并清理或作废含有被删内容的应用管理备份；删除当前会话或清除数据前先取消在途请求，防止迟到回复重新写回。用户在应用外保存的导出副本需自行删除，界面明确说明这一范围。
- “清除全部个人数据”包含应用管理的恢复/迁移备份、数据库附属文件、缓存、日志和凭据，避免删除后被旧备份恢复。删除是应用层面的数据清除，不承诺存储介质取证级擦除，也不能删除第三方服务留存的数据。
- 卸载默认保留个人数据，卸载界面清楚说明；用户可在应用内先清除数据。

### 11.4 隐私默认值

不收集遥测，不自动上传日志，不扫描磁盘，不读取剪贴板，不截屏，不启用麦克风或摄像头。当前活动名称和心情记录不自动附加到 AI 对话。

“不读取剪贴板”指不监听或后台读取；用户在输入框中主动执行粘贴时可正常输入，粘贴内容仍须点击发送才会联网。通知、托盘提示和主动气泡默认不显示聊天内容、心情备注或专注任务名称。

诊断日志仅记录运行状态、错误类别和必要的非敏感元数据；对服务地址中的凭据参数、请求头及消息正文进行排除或脱敏。

日志轮转总量上限 10MB、最长保留 7 天，先达到任一条件就清理。历史记录分页读取，不因记录增加而一次性加载全部内容；不静默删除用户历史。迁移备份仅在升级前生成，保留最近一份，应用内说明并可清除；删除规则同上。

## 12. 异常与恢复体验

| 情况 | 用户看到什么 | 恢复方式 |
| --- | --- | --- |
| 未配置 AI | 明确的未连接状态 | 配置连接或继续本地活动 |
| 网络中断 / 超时 | 当前消息失败，草稿保留 | 手动重试，不无限自动重发 |
| 密钥错误 / 配额不足 | 区分认证、限额或服务错误 | 打开设置，保留当前对话 |
| AI 输出中断 | 保留部分回复并标记 | 重试或继续新消息 |
| 数据写入失败 | 明确提示尚未保存 | 保留内存状态，允许重试或导出 |
| 数据格式或版本不兼容 | 说明无法打开或导入 | 保留原文件，不直接覆盖 |
| 应用异常退出 | 重启后恢复最后安全状态 | 专注以暂停状态恢复 |
| 显示器移除 / 缩放变化 | 窗口自动移回可见区域 | 设置中可重置位置 |
| 系统通知不可用 | 应用内仍显示完成状态 | 可查看设置，不反复申请 |
| 快捷键冲突（若后续加入） | 显示绑定失败 | 可重新设置，不影响其他入口 |

首版不依赖全局快捷键即可完整使用。应用需要保证重复启动不会出现多个角色或多份计时任务。

## 13. 实现结构与工程要求

本节描述实现边界，不锁定具体框架和依赖版本。正式编码前，用最小技术样例验证透明窗口、点击区域、托盘、多屏缩放和系统休眠事件，再确定桌面技术方案。

### 13.1 模块划分

```text
界面层
  桌面角色 / 小屋场景 / 聊天 / 专注 / 心情 / 放松 / 设置
     ↓ 用户意图与状态订阅
应用逻辑层
  伙伴状态 / 活动控制 / 专注计时 / 成长规则 / 会话管理
     ↓ 明确接口
基础能力层
  本地存储 / AI 适配 / Windows 窗口与托盘 / 凭据保护 / 通知
```

只有应用逻辑层决定活动状态和成长发放，界面负责展示和输入，避免不同窗口各自运行计时器或发放奖励。

AI 接口只负责对话，不接入文件写入、Shell、系统配置或其他工具执行能力。以后增加工具时单独设计授权和结果预览。

### 13.2 存储与稳定性

结构化记录采用支持事务的本地存储；设置和资源使用版本化结构。首次建立数据、升级迁移、导入和成长发放均应可重复执行而不破坏数据。

计时按状态变更即时保存，只有活动计时运行时才每 15 秒保存恢复点，目标最大异常丢失进度不超过 15 秒。计时显示由已用时长推导，不依赖高频轮询累计；空闲不写计时恢复点。应用正常退出前完成安全写入。

房间、动画和字体等基础资产随应用分发，不依赖远程加载。隐藏窗口时停止无意义渲染，减少动效模式降频或使用静态图。

角色状态可复用动作、静态姿态和表情，不要求每个状态一套独立长动画。首版不引入游戏引擎、动态插件系统、向量数据库、本地大模型打包或常驻后端作为默认依赖；确有必要时需提供对成本、资源和维护负担的比较后再提出范围调整。

锁定依赖版本并提供可复现的构建说明；资产记录来源与许可。升级迁移失败时保留原数据并停止迁移，不在旧版本上强行打开新结构。导出结构附版本说明，保证未来服务或界面替换时用户数据仍可读取。AI 适配与业务状态分离，但首版不提前实现未使用的服务适配。

### 13.3 性能目标

以下为待实测的验收目标，不代表已有数据。开发初期选定一台 Windows 11、4 核 CPU、8GB 内存、SSD 的参考机器并记录配置。

- 冷启动至可交互目标不超过 5 秒。
- 桌面待机平均 CPU 占用目标低于 1%，整体专用内存目标不超过 150MB；仅托盘状态目标低于 0.2%、100MB；小屋打开但无 AI 请求时整体专用内存目标不超过 250MB。统计包含应用拥有的子进程。
- 桌面待机 GPU 占用目标低于 1%，仅托盘时停止角色和场景渲染，无持续 GPU 活动；透明窗口和系统合成的开销单独实测记录。
- 待机动作最高 15 帧/秒，主动互动最高 30 帧/秒；静态场景按需重绘，不保留常驻 60 帧循环。仅托盘状态卸载未使用的小屋视图和大型动画资源，仅保留必要状态。
- 未主动发起 AI 请求时无外部应用网络请求；仅托盘且无活动时无周期性业务写盘，诊断日志按第 11.4 节限量保存。
- 本地点按反馈目标在 100ms 内出现。
- 包括 AI 在内的所有网络任务不得阻塞窗口拖动、菜单和计时；AI 等待与超时按第 6.5 节验证。
- 连续运行 8 小时无崩溃，计时与内存不出现持续异常增长。

各待机状态预热 2 分钟后持续采样 10 分钟，记录平均值、峰值和系统背景负载；冷启动重复 5 次，记录中位数及最差值。本地反馈测量第 95 百分位，AI 延迟单独记录测试次数、服务、模型和网络环境，不把第三方延迟写成应用保证。

若选型实测无法满足，先检查资产、渲染和生命周期管理，记录差距；不得直接放宽目标来通过验收。涉及明显体验取舍时交由用户确认。具体框架通过包含上述性能指标的技术样例后才能确定。

### 13.4 安装与发布

提供 Windows x64 安装包，创建应用入口和卸载入口。默认不需要管理员权限，不写入与项目无关的系统配置。自启动仅在用户主动开启后配置，并可撤销。

首版采用手动下载安装新版；升级保留个人数据并执行版本迁移。发布说明列出系统要求、AI 服务验证范围和已知限制。代码签名、发布渠道及实际依赖版本在发布前确定，不能把未验证的系统兼容性写作已支持。

## 14. 分阶段落地

| 阶段 | 工作内容 | 完成检查 |
| --- | --- | --- |
| A：桌面基础 | 单实例、托盘、透明窗口、拖动、多屏、存储基础 | 能启动、显示、收起、退出，位置与偏好可恢复 |
| B：伙伴与小屋 | 默认角色动作、房间、导航、设置、安静与减少动效 | 两种形态状态一致，所有核心入口可访问 |
| C：本地可用闭环 | 专注、休息、心情、三种放松、植物与装饰 | 无网络时完整完成日常活动，记录准确 |
| D：AI 陪伴 | 连接设置、聊天、历史、上下文、停止与重试 | 实际服务调用成功，故障有反馈，凭据不泄漏 |
| E：交付完善 | 导入导出、异常恢复、迁移、安装卸载、性能与可访问性 | 完整通过验收，生成可安装版本 |

初版达到可用需要完成 A–E，阶段性样例用于验证，不单独冒充完整首版。实际开发工期在技术样例和角色资产方案确定后估算。

## 15. 验收清单

### 15.1 必测用户路径

- [ ] 全新安装后跳过 AI，完成命名、打开小屋、开始专注、结束和查看记录。
- [ ] 桌面点击、拖动、收起、恢复、置顶和退出均有效，无透明大区域挡住其他窗口。
- [ ] 在桌面与小屋切换时，角色身份、房间、计时与聊天状态保持一致。
- [ ] 专注暂停、恢复、提前结束、正常完成都准确记录，完成只发放一次。
- [ ] 锁屏、睡眠、退出重启和异常结束后，专注不会把离开时长误算为有效时长。
- [ ] 心情记录可新增、编辑、删除；未主动选择分享时不出现在 AI 请求中。
- [ ] 三种放松活动无需网络可用，并可随时结束。
- [ ] 植物和装饰按规则推进，跨日、重复点击、导入和重启不重复发放。

- [ ] 网络错误、认证错误与限额错误可辨识，输入和已有回复不丢失。
- [ ] 中文输入法选词和换行不误发送；键盘可完成核心流程。
- [ ] 安静模式不出现主动招呼或声音，减少动效设置对全部场景生效。
- [ ] 导出不含密钥；导入失败不破坏原数据；清除全部数据后没有恢复备份残留。

- [ ] 新用户无需编辑文件即可调整常用偏好，使用预置服务完成 AI 配置，恢复偏好默认值不会删除记录。
- [ ] 本地互动与空闲场景无 AI 调用；每次发送请求数量、上下文预算、输出上限和无自动重试策略通过请求记录验证。
- [ ] 慢响应、流式停滞、取消和超时期间本地交互正常；删除会话后迟到回调不能重新产生数据。
- [ ] 更换服务地址不自动发送旧记录；测试连接不含个人内容；富文本不自动加载远程资源，凭据不跨源转发。
- [ ] 普通删除会处理应用管理备份，导入只替换明确包含的类别，旧版本遇到不兼容数据能安全停止。
- [ ] 分别测量桌面、小屋和仅托盘状态的 CPU、内存、GPU、网络与写盘，附成本估算和延迟测试条件。

### 15.2 测试投入重点

优先为计时与恢复、成长去重、导入事务、数据迁移和 AI 请求隐私边界编写自动化测试。角色表现、窗口穿透、托盘、多屏、输入法和通知通过 Windows 实机验证。避免只测试界面存在而不验证真实行为。

## 16. 评审结论与待定项

本设计首版采用：一个默认 3D 伙伴、一个固定 3D 小屋、完整本地陪伴闭环，以及可自行配置的文本 AI 对话。复杂工作处理后置。

开发前需要确定但不妨碍本设计成立的事项：

1. 角色最终外观、名字和美术资产来源；默认方向为温和、略有幽默的小生物。
2. 是否接受自行配置 AI 服务；本设计以此作为首版默认，若改为内置服务，需增加后端、费用和账号方案。
3. 通过 Windows 技术样例后确定桌面框架，不以展示页面的便利性替代桌面能力验证。
4. 是否需要支持 Windows 10 或 ARM64；未确认前不扩大首版测试矩阵。

本文仅建立可评审的设计范围。进入实现前，用户可调整上述默认方案和功能边界。

## 17. 开发准则复核记录

本次复核保留产品定位和功能范围，修订已规划功能的实现约束与验收标准。

| 准则 | v0.1 的不足 | v0.2 调整 | 取舍 |
| --- | --- | --- | --- |
| 接口成本 | 未规定调用数量、上下文和输出预算 | 单请求、固定预算、无后台推理、无自动重试，补充典型费用核算方法 | 长对话不会无限记住全部历史，回复默认简短 |
| 响应延迟 | 只约束本地点按，未规定 AI 等待和超时 | 反馈、首内容、停滞和总超时分开处理，可取消 | 慢服务可能被终止，由用户决定是否重试 |
| 隐私边界 | 切换服务、远程资源和备份删除存在空白 | 明确发送对象、禁止隐式联网、管理备份与迟到回调 | 换服务继续旧会话需要一次明确确认 |
| 长期可用性 | 已有离线基础，迁移失败和服务替换细节不足 | 数据格式版本化、迁移失败保护、服务适配隔离 | 首版只验证一个服务，不承诺任意服务兼容 |
| 定制简单 | 要求用户直接填写技术参数 | 已验证服务预设、基础与高级设置分层、偏好可恢复 | 自带密钥仍有门槛；内置付费服务需另行决策 |
| 资源占用低 | 300MB 统一指标宽泛，未覆盖 GPU 和隐藏视图 | 分状态预算、按需渲染、限制动画与磁盘/日志活动 | 托盘恢复可能需要短暂重建视图，优先及时显示反馈 |
| 隐私清楚 | 文档说明多，界面操作时提示不够明确 | 显示当前服务、心情主动分享、连接测试费用说明、删除范围说明 | 提示集中在真实数据流变化处，避免重复打扰 |
| 维护省心 | 缺少资产、依赖、日志增长和适配范围的约束 | 复用动画、锁定依赖、控制日志、记录许可、避免提前扩展架构 | 当前聚焦 Windows 单用户和一个房间，不提前建设平台 |

成本、真实服务延迟、资源占用和定制路径均待实现验证；本次完成的是设计审查与修订。

### 17.1 3D 范围调整

2026-10-09 用户明确要求“3D 宠物和小屋”，替代此前 2D 展示方案。新增范围为真正的立体几何、局部视角旋转、缩放和 3D 物件拾取；原有陪伴、专注、聊天、数据及隐私边界继续适用。动画以表情、姿态与轻量变形为主，不扩展为自由漫游游戏。

3D 资产在本机生成并随程序分发，不产生接口费用。响应、GPU 和隐藏状态的资源回收必须重新验证；后续实施证据统一记录在 `docs/实现与验证记录.md`，不能将设计目标或模拟服务检查误标为真实服务验收。
