# P1 第三批：统一静态能力目录

日期：2026-10-15。项目：D:\forme。应用版本：0.6.4。

本批把伙伴动作、工作辅助和项目资料协作的模型可选项登记到 Core 的一份能力目录。目录同时标注调用者、输入形式和数据边界；模型提示中的可用名称与各解析器的允许名单从该目录产生。

## 已落实

- 伙伴动作类型从 CompanionIntentType 生成，快捷键仅供本地映射，不暴露给模型。动作协议提示和 JSON 解析白名单使用相同类型来源。
- 记事/待办/提醒操作从 ProductivityIntentType 生成。提示里的操作名单和结构化解析前的允许项检查来自目录；已有参数、数量、当前用户表达检查及本机执行逻辑继续生效。
- 项目草稿与澄清能力从目录生成并放入项目请求上下文。项目 JSON 解析器只接受目录中标记为模型调用的能力。
- 待办投影被登记为用户调用能力，不加入模型可选目录。写入入口检查它必须由用户确认；仍按每条建议弹出确认并原子去重。
- 目录没有提升权限。现有动作权限、场景可用性、目标检查、项目分享许可和来源校验仍决定每次执行是否获准。

## 边界

这是一份静态接口清单，尚不是完整的动态工具宿主。伙伴动作和工作操作仍使用原有两类结构化响应协议；运行时家具、伙伴可见性、游戏状态等能力观察没有统一到同一个模型调用中，也没有新增跨模块步骤计划、执行证据链或电脑控制。模型仍只按当前消息识别相关动作/工作意图，项目模式只访问用户选择的资料。

没有新增网络请求、后台模型调用、权限或本地记录读取。动作识别沿用当前会话消息边界，资料项目沿用独立许可；待办等已有数据不会因为目录而自动进入模型上下文。
