# P1 目标中断后的本机产物核对

日期：2026-10-20。版本：0.6.16。

## 本批范围

目标执行中的本机记事、待办或提醒可能已写入数据库，但应用可能在写入后、步骤完成回执入账前退出。启动恢复会把运行步骤标记为“不确定”，并跳过未开始的后续步骤，防止自动重放；此前账本虽能显示产物仍存在，却没有将这项可验证事实记回步骤状态的用户入口。

本批在目标执行记录中提供“核对并确认此步已保存”操作。仅当目标已中断、步骤处于“不确定”、步骤能力是创建记事/待办/提醒，且对应稳定产物 ID 在本机数据库中仍存在时才显示入口。点击后在事务中重新检查状态与产物，并将步骤标为已完成，回执为 `recovered-artifact`。产物不存在、被用户删除、步骤类型不支持或记录状态变化时都不会确认。

此操作只校对已存在的本机记录，不创建、覆盖或删除产物；不会重新调用 AI，不会重新执行已中断步骤，也不会恢复原计划中被跳过的后续步骤。如果它是目标唯一的一步，目标可据此标为完成；否则目标仍为中断状态，用户可以查看进度并明确提出新目标。

## 后续边界

当前只核对有稳定本机产物 ID 的写步骤。桌宠动作、纸船或藏物等外部于该 SQLite 事务的结果仍需各自的场景状态核对；未知副作用不能依赖此入口重试。应用重启后续跑多步骤目标、恢复原计划正文和结果不确定状态下的去重协议仍未实现。
