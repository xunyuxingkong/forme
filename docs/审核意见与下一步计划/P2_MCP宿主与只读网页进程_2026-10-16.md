# P2 MCP宿主与只读网页进程

日期：2026-10-16。版本：0.6.13。

## 实际交付

项目页已有“读取指定网页”改为经过真实MCP客户端/工具服务端交互：创建工具进程、初始化握手、发现并核对唯一工具、调用、检查返回来源版本/正文哈希、终止并确认进程退出，最后沿用现有项目资料授权。官方 `ModelContextProtocol.Core 2.2.0` 同时提供客户端与底层服务端API；未引入托管Agent、Node或浏览器运行时。

首个工具为本程序内置的 `forme_read_public_page`，使用此前验证的公网HTTP读取器，保留逐跳检查、实际连接IP验证、Cookie/代理禁用、静态HTML提取及1 MB上限。工具声明为只读但宿主不靠声明授予权限：启动文件和能力名称均固定，未开放任意进程或工具配置。模型仍只处理用户明确授权的项目资料，未开放AI自动选择网页地址或后台调用该工具。

## 进程、数据和停止

- 专用启动分支在WPF、数据库、密钥、托盘和提醒初始化之前运行；只提供stdio，不监听端口。
- 地址只在MCP管道中传递，不出现在命令行；来源全文不落盘，不记录原始stdout/stderr。父进程不转交用户环境、代理或API密钥，仅保留系统目录、临时目录及.NET启动必需项。
- 子进程先等待启动门，Windows Job关联成功后才开始协议处理。Job设置关闭句柄即终止、一个进程和256 MB提交内存上限。父进程停止、20秒期限或异常会回收进程并等待退出；子进程另有30秒生命周期上限。无法确认退出则不接受来源。
- Windows Job并不是文件系统或网络权限沙箱。这里执行的是随程序附带的可信适配器，公网网络限制由读取器代码实施；不声称能约束任意第三方Agent。因此本版不开放外部服务配置、Playwright脚本、系统输入或任意文件工具。
- 工具返回的来源必须能从正文重算出相同元数据/哈希，才可进入项目；失败保留已有项目资料，用户可手动重试。新增来源后仍撤销原项目分享许可，必须重新允许当前模型发送。

## 验证与资源

MCP专项检查实际启动独立子进程，模拟页面响应位于子进程内；验证握手/能力清单、来源往返、环境凭据不继承、重复调用回收、HTTP失败、内网拒绝、读取取消、启动超时、进程突然退出，以及项目分享/失败保留/撤回。测试不访问真实网页或模型服务。
