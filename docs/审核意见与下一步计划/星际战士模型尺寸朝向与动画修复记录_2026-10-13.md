# 星际战士模型尺寸、朝向与动画修复

## 问题与来源

此前导入 `space-marine-mod-source/character-static.glb`，该文件无动画；静态导入还把节点合并为整块网格，无法播放关节动作。用户提供的目录 README 指向上一级 `space-marine.glb`，该完整文件包含步枪，以及 Walk（约 1.35 秒）和 Run（约 0.8 秒）循环动作，驱动 8 个刚性关节。它们不是蒙皮骨骼动画。

此前模型额外偏转 90°，桌面视图还偏转 -12°。模型高度被归一为 1.55；桌面模型所在行固定高度，大小设置不能充分放大；小屋未使用该偏好。

## 修复范围

- 改用完整源 GLB，排除展示底座，保留步枪、材质与原版关节关键帧。保留底色、法线及金属度/粗糙度的现有 WPF 材质映射。
- 保留动画节点层级；仅合并、烘焙固定节点，按原文件关键帧插值，不重建或每帧变形网格。Walk/Run 由小屋实际寻路与桌面实际走动状态选择，停止时恢复默认关节姿态。
- 模型基准高度改为 3.10（原来的两倍）。小屋同步应用现有伙伴大小偏好；“大”档为 1.3 倍，实测模型高度 4.03。纸船场景的 0.72 比例继续在偏好比例上叠加。
- 桌面为该模型提供两倍显示区域并同步调整相机，避免放大网格被裁切；改用可伸缩布局，已有大小设置继续生效。
- 去除额外朝向偏移。桌面默认正面；小屋待机面向当前视角，移动时沿行进方向转身。
- 设置中的静态模型说明更正为原版行走与奔跑。

## 成本、延迟、隐私与维护

加载用户已提供的本地模型，不联网、不增加 AI 请求或费用。动画数据直接随应用打包，无需外部模型服务。网格和材质冻结共享，每个显示实例仅维护 8 个独立关节变换；不会把动作定时器叠加到既有动画调度之上。隐藏、暂停和减少动效沿用现有停止机制。移除已由完整模型包含的独立步枪资源嵌入，避免重复打包。

以上为实现边界；未声称已完成长时间驻留、GPU 帧率或多 DPI 性能基准。完整 WPF 冒烟结束时的进程私有内存快照是该次全流程测试结果，不等于单模型常驻内存。
