# P1 第一批：项目资料、目标账本与草稿协作

日期：2026-10-15。项目：`D:\forme`。应用版本：0.6.2。

本轮落实设计 P1 的第一条工作链：选定资料 → AI 判断生成草稿或询问 → 引用核验 → 原子保存 → 修改目标后继续。保留已完成的 P0；通用组件 Agent 与电脑控制仍属后续工作。

## 使用入口

在小屋底部点击“项目协作”。

1. 填写目标，选择0至3条待办建议，点击“新目标 / 选择资料”。当前支持文本与 DOCX；正文在本地提取，尚未上传。
2. 检查资料正文和“发送预览”，允许本项目向当前服务发送这些资料与本项目草稿，再点击生成。
3. 草稿显示来源文件、提取后的段落、正文哈希短码与原文短引，可在“记事”继续编辑。DOCX 段落编号不代表 Word 页码。
4. 修改目标后点击“应用新目标”。在途旧请求会被取消；下一次生成使用新版本，旧响应不能覆盖新目标。每次成功修订生成独立笔记，手工改过的旧笔记保持原样。
5. 结束项目会清除内存资料和分享许可；草稿继续保存在记事。也可由页面直接进入已有藏物玩法，其分享范围不继承工作资料。

## 实现范围

| 模块 | 本轮实现 |
|---|---|
| 资料观察 | 仅用户明确选中的文本/DOCX；规范化正文、稳定段落、哈希和提取器版本；不保留原路径 |
| 最小能力目录 | `notes.draft` 与 `user.ask`，目录随本项目请求生成；模型按语义选择，不使用新句式匹配规则 |
| 结构化结果 | 完整 JSON 与严格字段验证；拒绝未知能力、重复字段、错误来源/段落/原文、数量不符和截断输出 |
| 目标账本 | 项目 ID、目标版本、调用次数、状态、来源元信息、产物 ID、最后请求服务与模型；使用现有本机 SQLite 设置表 |
| 写入与幂等 | 账本和笔记同一事务；检查版本、尝试次数与状态；重复或过期结果不重复写入；不创建正式待办或提醒 |
| 最小恢复 | 中断状态重启后等待重新选源，不自动重发；相同快照且期限/额度有效才续接；其他情况明确建立新目标 |
| 可见状态 | 专用项目页面、草稿、来源预览、调用额度、阶段提示；原始协议不混进聊天正文 |
| 导出与删除 | 项目 JSON 单独导出元信息与当前草稿；普通工作记录导出包含笔记草稿；项目记录删除与笔记删除分开 |

本轮未增加数据库表或数据库迁移版本，原记事和备份格式继续可用。新增账本不进入原通用导入/导出，使用“导出本项目”单独保存；项目 JSON 暂不支持自动导入。一般工作记录导入后，已有项目可能引用被替换/删除的笔记，页面会反馈缺失，不自动重建或重放。

## 成本、时限与资源

- 每个目标最多两次请求，失败、取消、澄清同样计次；修改目标不重置额度。用户明确重新选择资料建立新目标时才建立新额度，最多保留20条项目记录。
- 首次生成后120秒为本次工作窗口；请求有取消期限，资料清理定时器绑定项目，修改目标不重启该窗口，新项目不沿用旧项目定时器。
- 沿用用户的服务、模型、文字预算、思考设置和输出上限。资料或草稿超预算时在发送前拒绝，不默默裁剪；输出截断不写草稿，不自动加大输出或重试。
- 不启动后台资料分析或额外模型。资料沿用附件大小限制；只在本任务内存持有正文，运行中暂停已有后台自主选择的争用。未测得整体 CPU/内存增量，不能据此承诺性能百分比。

## 隐私与产物真实性

项目分享许可仅在本进程内绑定当前服务/模型；不从记忆或项目导出恢复。原资料不进入普通聊天、长期记忆或任务账本。账本元信息和已保存草稿为本机普通数据，包含的原文短引仍属于保存的产物；结束项目不能撤销服务商已收到的数据。

程序核验原文短引确实出自对应段落、建议数量及保存状态；这些检查不等于证明摘要没有语义错误。界面明确要求审阅内容。模型可以选择提出必要问题；它不能因为资料中出现指令就获得新的文件、桌面或应用权限。
