## 一、项目理解与改造范围

Forme 是 Windows WPF 常驻桌面伙伴，使用 .NET 10；`Forme.App` 负责窗口、角色和场景表现，`Forme.Core` 负责本地数据、规则、玩法和 AI 请求。SQLite 保存个人数据，AI 为可选外部能力。此次保留现有桌宠、小屋、生活互动、家具预览和纸船玩法，整改这些能力的意图入口与执行约束。

没有添加 P2 的 Photo Mode、环境音或新宠物行为，也没有新增服务、模型依赖或后台联网任务。没有修改旧 C 盘工程，没有创建 tag、推送或发布 GitHub Release。

## 四、成本、延迟、隐私与长期可用性

- **成本**：安全快路径、规划、执行和环境反馈本地完成。配置 AI 后，普通聊天和语义动作判断各由一次用户触发请求完成；不自动重试，不另发动作结果反馈；自动验收采用 mock，未调用付费服务。实际费用由用户配置模型和服务计费决定。
- **延迟**：本地操作不等待网络，AI 继续使用已有异步请求、取消及预算限制。动作完成反馈等待真实状态，最长 30 秒。本次没有实测真实服务延迟，也不承诺各服务响应时间。
- **隐私**：AI 语义判断走当前聊天上下文构造，可包含预算内历史、角色设定及用户主动启用的记忆/会话摘要；附件仅随用户明确发送的本次消息上传，后续消息不自动重传；不会自动上传场景坐标或其他本地数据。日志不保存模型协议或凭据；崩溃隐私检查通过。
- **长期可用性**：本地动作与玩法无需 AI 或网络；AI 返回无效协议时明确失败，不执行片段。内容 ID 基线、规则升级、可替换服务和统一发布检查降低维护风险。保留原数据格式兼容入口，无破坏性数据迁移。

## 七、绕屏误报打断修复

2026-10-10 用户反馈“跑2圈在屏幕上”立即返回被打断。针对性 WPF 检查复现了绕屏失败。桌宠将拖动手势历史标志同时用作正在拖动的判断，原生 DragMove 消耗鼠标释放后会残留标志；另一个触发点是气泡八秒后自动收起改变窗口尺寸，使路线工作区被判变化而停止。

修复仅涉及桌宠动作：分离正在拖动与手势历史；有限路线期间延迟气泡导致的窗口尺寸调整，结束后恢复正常布局。真实拖动、停止、隐藏、暂停、权限撤销与工作区变化仍可中断动作，没有取消这些保护。

回归覆盖原句两圈完成、拖动结束残留标志、气泡自动收起、手动停止返回 Interrupted，以及停止后重新移动成功。针对性 `--smoke --rules-only` 检查通过；重新执行统一验证并生成安装包。没有新增联网请求或用户数据字段。
