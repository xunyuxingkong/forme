# AI 意图识别与动作控制问题分析

日期：2026-10-10。分析依据：D:\forme 当前源码和用户反馈截图。

## 现象与结论边界

用户发送“去池塘边”，伙伴回复要切换户外、慢慢走过去，但截图中伙伴仍在长椅附近。用户此前也反馈过桌面动作承诺与实际表现不一致。

源码中存在户外池塘互动及移动到池塘附近的实现，因此不能仅凭截图判定动画系统失效。较可能的情况是 AI 只输出场景切换命令，遗漏池塘互动命令，或命令在权限、路径、窗口状态检查中未执行。截图没有请求原文和执行链路，无法确认本次实际原因。本次未读取用户聊天数据库或密钥，也未调用外部 API。

## 当前调用链

用户输入 → 本地短语规则匹配 → 未命中时调用聊天 API → AI 正文生成完成 → 解析正文中的 forme-actions JSON 代码块 → 校验权限及参数 → 顺序执行并等待动作结束 → 保存正文与执行报告 → 界面过滤内部报告。

目前使用正文中的结构化代码块协议；请求未接入原生 tools/tool_choice，响应解析也未处理 tool_calls。口头描述本身不会触发程序动作。

## 已确认的缺陷

| 优先级 | 缺陷与源码依据 | 对体验的影响 |
| --- | --- | --- |
| P0 | Forme.Core/ActionRules.cs 默认短语没有“去池塘边”等别名；匹配以规范化后的精确短语为主 | 明确的本地操作可能漏识别，转为付费联网聊天 |
| P0 | Forme.Core/CompanionCommands.cs 的 go 仅支持室内目标；池塘需 interact pond，提示词没有明确自然语言映射 | 用户表达与命令语义不统一，模型易只切场景或选错命令 |
| P0 | 没有合法 forme-actions 代码块时 Parse 返回空命令；普通动作承诺未必触发未执行提示 | AI 说要动，程序实际无命令可执行 |
| P0 | Forme.App/Controller.cs 在回复生成后才执行，执行结果没有回传给 AI 完成本轮确认 | 提示词虽然要求执行成功后再确认，架构仍无法保障回复与实际结果一致 |
| P1 | Forme.App/LocalActions.cs 使用字符串执行报告；部分场景处理函数通过普通字符串返回失败 | 无法稳定区分开始、到达、失败、取消；多步骤指令可能只完成切场景 |
| P1 | pond 的 interact 依赖场景控制权限，即使其主要行为是移动；多个步骤没有整体预检 | 用户只允许伙伴控制时，可能出现能切换或能走但组合目标不能完成的困惑 |
| P1 | Forme.App/ChatDisplay.cs 隐藏内部动作报告；本地与 AI 的 ChatStatus 标记方式不同 | 隐藏技术文字后，用户缺少清晰的执行状态，难以定位未识别、被拒绝或受阻 |
| P1 | 当前检查主要直接调用池塘互动或使用固定 AI 命令块 | 未覆盖“自然表达 → 场景处理 → 移动 → 到达”的完整验收链路 |

相关执行入口：Forme.App/CompanionControl.cs；池塘目标与互动：Forme.App/SceneDetails.cs；等待完成：Forme.App/AiCreation.cs；现有检查：Forme.App/CompanionChecks.cs。

## 建议整改顺序（尚未实现）

1. 统一目标语义与常用自然表达。“去池塘边”“到池塘旁边”等应在本地确定目标；已在户外则直接移动，室内则按权限切换后移动。复用真实场景目标，避免提示词与代码分别维护坐标。
2. 统一动作结果结构，至少区分未识别、未授权、执行中、到达、路径受阻、取消及超时。执行前校验组合步骤的权限和可用目标；途中状态变化仍需逐步校验。
3. 在聊天旁提供简洁状态，例如“正在去池塘边”“已到达”“没走成：路径被挡”。继续隐藏协议与内部报告，但保留用户能理解的结果。
4. 让回复依据实际执行结果确认；模型只提出动作意图，程序负责执行判定。对没有合法命令的动作请求给出明确未执行状态，不能把口头承诺当作成功。
5. 评估原生工具调用的可选适配；保留兼容代码块协议和本地规则。不同服务的能力需实际验证，不能假定所有兼容接口均支持 tools。
6. 增加自然表达的端到端检查，覆盖室内/户外、桌面悬浮、小屋隐藏、权限关闭、停止/取消、路径受阻以及模型未发出命令的情况。

## 取舍与验证要求

- 接口成本与延迟：确定性指令优先本地处理；如需结果回传给模型，明确额外请求次数、上下文预算及停止条件，执行反馈不能等待第二次联网才显示。
- 隐私：诊断仅记录必要的意图、命令、状态和耗时；不默认保存完整请求、聊天内容或凭据，不扩大 AI 数据发送范围。
- 长期可用性：断网时常用本地动作可用；统一目标与结果契约，减少提示词、规则和场景代码之间的重复维护；服务能力不足时仍能明确反馈。
- 资源与定制：复用现有异步等待及取消机制，避免新增轮询；常用动作无需用户手写坐标或编辑规则。
- 验收：以实际位置变化和到达结果为准，不能只验证回复文字或命令解析成功。用户要求性能测试后置，本次不开展性能矩阵。
