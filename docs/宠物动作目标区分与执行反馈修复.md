# AI意图路由与宠物动作执行修复

日期：2026-10-12

## 现象与原因

“在小屋走一圈，然后去书架旁边”会被模型当作普通聊天回复。旧流程先用本地正则判断是否像动作句，没命中时就按普通聊天发送；模型因此可以口头答应，却没有生成本机可执行的动作计划。继续枚举句式会让自然语言覆盖面越来越依赖硬编码。

## 修复

- 配置 AI 后，未被附件隔离的文本消息由同一个 AI 请求统一判断意图：普通聊天返回自然回复；动作请求返回 `forme-actions` 计划。AI 可结合有限的会话上下文理解省略表达和多步动作，不依赖“在小屋走一圈”等本地短语匹配。
- AI 动作计划只含受限的动作类型和目标，不接受脚本、任意坐标或程序指令。仍由本地权限、目标能力/可达性、整组预检、每组最多三步、停止及超时机制决定是否执行。
- 未配置 AI 时保留可选本地快捷规则，维持离线基本控制。带附件的消息继续按附件聊天处理，不从附件触发宠物动作。
- 普通聊天保持流式回复；动作计划不作为聊天正文展示，只有收到完整合法计划后才交给本地执行器。

## 数据、费用与验证

- AI 意图路由复用普通聊天当前已配置的有限会话上下文、角色设定和已启用的确认记忆；不额外发送小屋布局、屏幕状态或任意本机文件。首次确认说明与发送预览已更新。文字预算会为动作说明预留空间并裁剪历史；每条未命中离线快捷规则的文本消息仍是一次请求，不增加第二次分类调用。相较旧的“仅本轮输入”动作请求，上下文会更大，可能增加费用。
- `dotnet test tests/Forme.Tests/Forme.Tests.csproj -c Release --no-restore`：87 项通过。
- Release WPF 项目构建：0 警告、0 错误；离线意图流水线通过，覆盖复合小屋散步/书架目标、普通聊天不执行动作、权限与目标预检。
- 使用本地模拟响应验证，没有调用真实模型服务；真实模型能否正确判断具体表达仍取决于服务商响应，实际费用与时延未实测。
