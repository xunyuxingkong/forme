# 宠物动作目标区分与执行反馈修复

日期：2026-10-12

## 现象

“绕屋子走一圈”没有本地规则，原先会发给硅基流动识别。GLM 只返回思考内容、没有正文时，动作意图不会进入本地校验和执行；聊天状态提示也没有明确说本轮动作未执行。小屋与桌面伙伴并存后，普通动作会优先作用于小屋，屏幕环绕则应由桌面伙伴执行。

## 修复

- 增加本地理解：“绕屋子/小屋/房间走一圈”切换到小屋并执行场景内自由散步；界面和完成提示说明这不是完整闭环路线。
- “绕屏幕走一圈/两圈”仍是桌面伙伴能力。现在小屋保持打开时，也能将屏幕环绕交给可见的桌面伙伴；桌面伙伴隐藏、收起或请求组合了其他动作时，会明确拒绝并说明原因。
- 小屋聊天与悬浮聊天分别标明默认控制目标。固定动作提示词区分房间散步和屏幕环绕，不把当前窗口、场景或其它新状态加入请求内容。
- 动作请求等待时显示“正在识别宠物动作；尚未执行”。模型未返回正文、取消或请求失败时明确说明宠物动作未执行；成功完成屏幕环绕会区分圈数。动作权限、路径校验和等待停止机制仍由本机执行。

## 约束与验证

- 自然语言动作命中本地规则/解析时不调用AI；未命中才使用原有意图请求。没有增加重试、第二次模型调用或后台请求。
- 意图请求仍只发送用户本次输入与固定动作说明；没有增加场景、窗口状态、历史或密钥数据。
- Release WPF 项目构建成功，0警告、0错误。未调用真实硅基流动账户；实际模型响应与计费表现不作保证。
