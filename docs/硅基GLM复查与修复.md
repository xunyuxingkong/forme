# 硅基GLM复查与修复（2026-10-12）

用户使用 `https://api.siliconflow.cn/v1`、`zai-org/GLM-5.3-Flash` 测试时收到“服务未返回文本，请检查模型是否支持非思考文本对话”。截图只能确认缺少正文，不能证明其根因；未获取真实API响应、密钥或付费复现。此前“接口兼容即可手动接入”的说明不够充分。

## 已确认的代码缺口与修复

- 连接测试原先只有智谱官方采用用户输出上限，硅基GLM固定128。现在已适配GLM也使用已保存的正文上限；不自动增加额度，测试采用当前未保存的档位但不保存配置或密钥。
- 原GLM档位只影响智谱官方。对精确硅基入口和 `zai-org/GLM-5.3-Flash`、`zai-org/GLM-5.3`、`Pro/zai-org/GLM-5.2` 请求启用思考，low/high/max分别使用256/1024/2048 tokens思考预算。只有API文档明确列出的Pro/GLM-5.2传入high/max强度，low按平台规则映射为high；不向另外两款猜测传入reasoning_effort。
- 原硅基GLM推理进展不更新停滞计时。现在有效推理片段更新停滞计时，保留90秒总时限；思考不显示、不保存、不回传，不用于动作执行。
- 缺少正文不再误导为“不支持非思考”。区分“已返回思考但没有正文”与“无正文”，提供降档、核对正文上限、模型ID和权限的手动排查建议；仍不自动重试或伪报连接成功。

## 官方依据与限制

- [模型中心](https://www.siliconflow.cn/models)列出用户所填的完整模型ID。
- [对话补全API](https://docs.siliconflow.cn/docs/api/chat-completions-post)区分正文max_tokens与thinking_budget，说明后者适用于多数推理模型；reasoning_effort当前明确列出的GLM为Pro/GLM-5.2。
- [推理模型指南](https://docs.siliconflow.cn/docs/userguide/capabilities/reasoning)说明部分模型可能继续输出思考，因此预算是提示而非硬上限。不保证该模型遵守预算，也不以静默提升上限、重试或延长时限绕开失败。

成本与延迟：复用现有客户端，没有新依赖、后台请求或重试；仅用户主动发送/测试才联网。档位预算和用户正文上限独立，服务端可能超出思考预算，真实费用和延迟待用户账户测试，不能保证预算为账单硬限制。

隐私与维护：不读取真实密钥或私人API响应进行诊断，测试使用假HTTP处理器和隔离数据；服务商身份、数据库格式和现有档位存储兼容。其他模型参数与附件处理保持既有行为，当前修复只验证上述GLM文字通道。
