# 0.5.1 自然动作交互

修正聊天时要求用户填写坐标、AI把宠物请求当成“纯文字助手没有身体”的交互问题。

新增受宠物动作权限约束的语义意图 `stroll(walk/run)` 与 `go(book/feed/sleep/fish/window/door)`。AI理解“你能走两步吗”“跑几步”“去书架旁”等自然表达，本地选择可达目标；距离、可达性和步态由程序决定，用户无需提供坐标。短途移动有结束点，不改成永久随机走动。去家具旁只移动，不自动触发家具行为。

指令提示明确AI代表当前宠物；“过来”“跳个舞”“睡觉”“别动”使用已有指令。权限未开启时应解释如何开启，而不是说没有腿。否定、引用或讨论动作不应执行。本批不添加关键词自动执行器，仍由外部模型理解，生成结果需本地白名单验证，实际动作结果在回复下方显示。真实模型对自然语言的识别成功率未实测，不保证每次理解正确。

家具按当前保存布局寻找互动位置，窗边和门边选择可达的候选点；短途搜索最多16个候选点，不启动后台寻路循环。没有可达位置、家具已收纳、正在编辑家具/玩纸船、窗口隐藏/最小化或未授权时拒绝操作。室内物件移动要求在小屋；桌面短途移动未增加，悬浮模式仍使用原有舞蹈和随机走动待机功能。

沿用每次最多3步、动作组30秒、取消与权限复检，动作结束才执行后一步。寻路不会产生API请求或增加发送的私人数据。仅增加指令说明，仍受原有上下文预算约束；状态太多时沿用省略场景数据的处理。没有新增依赖、数据库结构、后台计时器或服务。性能专项继续后置，不把候选数量限制当成资源实测结论。

验证：46项Core测试通过，包含自然动作权限、非法参数、绕开障碍、找不到目标、搜索不改变实际位置或启动移动，以及走/跑步态控制；真实WPF专项验证“走几步”“去书架旁”，离线模拟流式回复验证先短途走到目标再拍一拍。Release编译0警告、0错误。没有使用真实API密钥或发生付费服务请求。
