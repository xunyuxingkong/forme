# 宠物动作与模型替换

动作系统支持待机呼吸、转头与眨眼、点击轻跳、揉揉挤压、拖起和落地反馈，以及睡觉、摇摆舞、蹦跳舞、转圈舞、吃零食、读书、趴下休息、观察。桌面伙伴、放松页和小屋内角色共用动作系统。专注与休息只保留呼吸，角色表情由当前状态决定。动作全部本地执行，不调用 AI，不采集输入记录，不新增依赖；桌面待机模式通过本机设置字段PetIdleMode保存。

## 分工

- `src/Forme.Core/PetMotion.cs`：动作选择、优先级和时间采样，输出 `PetPose`。不引用 WPF、网格、骨骼或角色名字。缩放为倍率，Lift 为模型高度比例，Yaw/Lean 为角度，Blink/Expression 为语义状态。无动作时使用 `PetPose.Neutral()`。
- `src/Forme.App/PetAnimation.cs`：`PetAnimator` 管理单调时钟、帧率、可见性和资源释放。`IPetModelFactory` 创建模型，`IPetModel` 负责姿态映射和拾取归属。
- `src/Forme.App/SproutPetModel.cs`：当前角色的适配器，把标准姿态转换为该角色的变换、旋转中心与表情。
- `src/Forme.App/SproutMesh.cs`：当前角色的几何与颜色。替换角色不需要修改动作曲线。
- `src/Forme.App/CompanionModels.cs`：模型目录和小猫、小狐狸、小企鹅的适配器；`PetModels.For(id)` 为界面选择提供工厂，形象选择保存在 `Preferences.PetModel`。
- `Pet3DView`、`Room3DView`：场景放置、输入与生命周期；提供 `ReplaceModel(factory)`，替换时停止旧动作并释放旧模型。小屋拾取询问模型归属，不依赖固定网格或表情索引。

## 替换模型的步骤

0.3 增加语义动作 `Launch`（放船）与 `Cheer`（抵达欢呼），通过 `PetPose.Reach`（默认0）表达伸手幅度。芽芽和小猫已映射到独立手部变换，共享冻结网格；狐狸和企鹅保持身体动作作为降级。新模型可映射手部或骨骼，也可忽略 Reach，不能让玩法逻辑依赖具体网格。此轮尚未实现通用模型文件导入或完整骨骼资产管线。

0.4 芽芽增加独立叶耳、小猫增加独立耳部与尾巴，适配器根据Expression、Lean、Stride映射部件变换。芽芽叶耳体现开心/好奇/休息，小猫耳部体现好奇/放松，尾巴跟随步态；猫耳几何位于CatDetails。冻结静态部件可共享，可修改的旋转对象属于模型实例；Contains需要覆盖新增叶节点。抛球和藏物复用Launch/Look/Cheer语义动作，玩法不依赖耳尾节点。

1. 实现 `IPetModelFactory.Create()` 和 `IPetModel`。`Root` 提供模型根节点；实例之间不要共享可修改的根节点。
2. 在 `Apply(PetPose)` 中把标准姿态转换为模型自己的尺寸、朝向和旋转中心。没有骨骼的模型可以驱动整个根节点；有骨骼的模型可以映射到身体、头等部位。没有眼睛或表情能力时可忽略 Blink/Expression，身体动作仍可复用。
3. `Contains(Model3D)` 应覆盖当前可见的几何叶节点，包含表情切换后的节点。`Dispose()` 清理模型引用及自有资源，不能留下计时器。
4. 使用同一工厂注入桌面和小屋，或调用它们的 `ReplaceModel`。在 `PetModels.Catalog` 与 `PetModels.For(id)` 注册新模型，并同步 Core 设置验证允许的 ID；现有 UI 会提供选择入口。正式角色仍保留 `SproutPetFactory.Create()`。

此接口解决动作与角色耦合，不代表已经支持任意模型文件直接导入。后续引入 glTF 等格式时，应由独立适配器处理格式加载、骨骼映射、模型居中和尺寸规范；动作控制器无需知道文件格式。没有新增模型下载器或编辑器。

## 资源与交互边界

平衡模式待机目标10帧/秒、显式动作上限30帧/秒；省电模式为5/20帧，睡眠和趴下休息2帧、读书与观察5帧、吃零食15帧。直接输入即时采样，计时器只驱动局部模型变换，不重建整间小屋或每帧创建几何。冻结基础网格与材质继续共享；角色表情缓存有界，每种表情的静态几何也被冻结，只修改根节点变换。重复输入替换当前动作，不积压队列；拖起优先于点击，动作完成后恢复基础状态。

安静模式暂停自动动作，显式互动结束后停止计时器；减少动效只改变静态表情。隐藏、收起到边缘、关闭、最小化、锁屏与睡眠停止时钟并取消当前动作，恢复时重新开始，不补播离开期间的动画。放松页切换内容时释放旧角色。

当前帧率是调度目标，不是硬件性能保证。增加动画会增加 GPU 合成和 CPU 工作量，应以资源回归观察和后续正式验收为依据。该实现没有增加网络调用、后台 API 成本或上传边界，模型替换也不能隐式加入网络下载或权限。

## 验证

核心测试覆盖动作时限、重复输入、拖动优先级、静止状态、有限数值与独立于采样频率的时间行为。`--smoke` 使用与现有角色形状不同、没有表情和骨骼的方块模型，检查动作复用、模型替换及旧实例释放；同时检查小屋换模型后的聊天拾取、表情网格拾取归属、几何复用及隐藏、安静、减少动效、收起、最小化和暂停后的计时器状态。

真实鼠标原生拖窗手感、硬件锁屏/休眠恢复、多屏 DPI 及长时间 GPU 稳定性仍需实际设备验收；程序化生命周期检查不替代这些验证。

场景行走新增：`PetTravel`仅使用米制地面坐标和障碍矩形，位置/朝向由模型外层容器更新。`PetPose.Stride`为可选的归一化步态，范围[-1,1]，模型适配器可映射到脚部或骨骼；不实现Stride的模型仍可平移转向，不需要重写寻路。默认模型身体与脚部几何冻结共享，脚部的可变变换属于各自实例。

桌面待机与舞蹈：`DesktopWander`仅计算工作区坐标、随机目标和步态，`PetWindow`负责当前屏幕/DPI边界及无激活窗口移动；不移动鼠标，不逐帧保存位置。`PetMotion`输出三种6秒舞蹈和睡觉的标准姿态，模型无需了解模式选择界面或屏幕坐标。复用现有计时器，睡觉2帧/秒，随机移动和主动动作30帧/秒（省电20帧）；隐藏、收起、暂停渲染时停止。旧设置缺少PetIdleMode时默认原地待机。自定义模型可自行映射Stride与旋转，也可忽略不支持的语义姿态。
